Визуальные блоки ​

Правая панель чата: данные из message.dataObjectVisual попадают в chatStore.lastAiAnswer, ChatView монтирует соответствующий view.

Каталоги: src/features/{map,genplan,parametric,…}/ + оркестрация в src/features/chat/views/ChatView/.

Отдельных HTTP API у модулей обычно нет — payload уже в ответе ассистента. v-bind="visualData" пробрасывает весь объект, поэтому у view должен быть prop с тем же именем, что и ключ (map, premises, images, …).

vue
<component :is="visualComponent" v-bind="visualData" :key="contentKey" />

Источник lastAiAnswer ​

СитуацияПоведение
Ответ ассистента (sendMessage)lastAiAnswer = assistantMessage.dataObjectVisual
Создание чатасразу lastAiAnswer = gallery (базовая галерея)
fetchChatByIdпоследний message с visual, иначе fallback gallery
openChatAtMessagevisual активного сообщения или null
setLastMessage(visual)null → setTimeout(0) → новый visual (форс re-watch)
setBaseGalleryстартовая галерея (empty-state / первый visual)
clearAllChatslastAiAnswer = null

IChatGallery — { images: […] } — тот же ключ images → SliderView.

applyVisual в ChatView ​

  1. Источник: lastMessage = getLastAiAnswer || {}.
  2. Триггеры: watch(lastMessage), onMounted.
  3. applyVisual(message):
    • отменяет предыдущий requestAnimationFrame;
    • сразу setVisualData — пишет visualData, закрывает fullscreen;
    • на следующем кадре — setVisualComponent + contentKey++ (remount).

rAF нужен, чтобы сначала отработали лента / анимация сайдбара, потом тяжёлая панель (Parametric, Map).

Выбор ключа (setVisualComponent) ​

Список релевантных (порядок = приоритет при нескольких ключах):

images → premises → genPlan → genplan → widget → stocks → documents → howToBuy → map → finishing → advantages → progress

  • пустой объект → выход;
  • ключей > 1 → первый из списка приоритета, иначе keys[0];
  • иначе → keys[0].

visualKey (default | dark) влияет на тему ChatAnswer / ChatAction на мобилке в режиме block.

FullscreenImage смонтирован всегда рядом; открывается через provide('openFullscreenImage').

Сброс панели ​

eventBus chat:clear-visual (logout / deleteAccount): закрывает fullscreen, обнуляет visualData.

miniInfo и plan (не выбирают панель) ​

В том же dataObjectVisual, но не входят в allRelevantKeys — правую панель не выбирают. Используются в ленте и fullscreen.

miniInfo ​

В ChatMessage: если есть dataObjectVisual.miniInfo → ChatMiniInfo.

ПолеСмысл
image / title / description / premises?Превью карточки в ленте

getMiniInfoType — первый ключ объекта кроме miniInfo (тип иконки / фона); если только miniInfo → кнопка disabled.

Клик по карточке:

  1. Копия visual без ключа miniInfo.
  2. chatStore.setLastMessage(object) → watch → applyVisual → правая панель.
  3. На mobile: setActiveView('block').

Для типов из typesList (live, commerce, premises, map, …) — SVG-фон MiniInfoBackground; иначе картинка miniInfo.image.

plan ​

В ChatMessage: ChatPlan при dataObjectVisual.plan ({ image, title }).

  • Клик → inject('openFullscreenImage') из ChatView (на mobile сначала setActiveView('block')).
  • Ссылка download на plan.image.

На mobile в ChatAnswer на последнем абзаце может быть превью plan (isPlanOpen) — это не правая панель и не FullscreenImage.

См. Полноэкранный план (FullscreenImage).

Схема потока ​

assistant.dataObjectVisual → lastAiAnswer
       ↓
ChatView watch → applyVisual
  → setVisualData (visualData)
  → rAF → setVisualComponent + contentKey++
       ↓
<component :is v-bind="visualData" />

Параллельно в ленте:
  miniInfo → ChatMiniInfo → setLastMessage → снова applyVisual
  plan     → ChatPlan → openFullscreenImage / превью в ChatAnswer
